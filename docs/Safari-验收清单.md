# Safari 手动验收清单

本清单用于发布前在真实 Safari 中复查主要写作流程、移动布局和保存保护。每次记录 Safari 与系统版本、设备型号、屏幕尺寸、应用 commit，以及通过或失败的项目；失败时附截图和复现步骤。

## 准备独立测试数据

在项目目录运行开发服务器，并为这次验收指定独立数据库和附件目录：

```bash
PORT=3037 \
DEV_DATABASE_PATH=./data/safari-acceptance.sqlite \
DEV_ASSETS_PATH=./data/safari-acceptance-attachments \
bun run dev
```

`bun run dev` 默认使用开发账号并开启本地自动登录；若页面要求登录，默认用户名为 `dev`。服务启动后，在 Mac Safari 打开 `http://localhost:3037/app`。脚本会打印局域网地址；iPhone/iPad 与 Mac 连到同一 Wi-Fi 后，用该地址加 `:3037/app` 打开。若端口已占用，换一个 `PORT` 值。

不要把 `DEV_DATABASE_PATH` 或 `DEV_ASSETS_PATH` 指向日常使用的数据。若指定的验收数据库已存在而需要保留其中数据，请换一个新文件名。结束后先在终端按 `Ctrl-C` 停服；只有确认路径仍是这两个验收专用路径、且不再需要测试内容时，才手动删除数据库文件及附件目录。不要在服务运行时复制或删除 SQLite 文件。

## 桌面 Safari

- [ ] 首次打开、刷新、退出再登录后，工作区和笔记内容都能正常显示；浅色、深色和跟随系统外观切换正常。
- [ ] 新建笔记，输入中文、英文、Markdown 标题、列表、任务清单、表格、引用、代码块和双向链接；输入法选字期间不会误触格式或全局快捷键。
- [ ] 等待保存状态显示完成后刷新页面；标题、正文、标签、笔记本和收藏状态保持一致。
- [ ] 上传、粘贴和拖入图片；图片可显示、可调整宽度。外站图片默认不自动请求，手动加载后才显示。
- [ ] 使用标题大纲、正文查找、全局搜索、反向链接和笔记移动；滚动区域可正常操作，没有内容被固定栏或弹层遮住。
- [ ] 从命令菜单导出全部笔记和随记；解压 ZIP，检查笔记、随记、回收站内容及附件，并用 Markdown 阅读器打开含图片的笔记，确认图片可见。随记未发布草稿不应被当作已发布内容。
- [ ] 连续使用 `Escape` 关闭子弹层、沉浸模式和大纲；焦点回到触发操作的控件，输入法组合输入时不意外退出。
- [ ] 用键盘 `Tab` / `Shift-Tab` 操作主要工具栏、搜索框、编辑器和弹窗；焦点清晰可见，弹窗打开时焦点留在弹窗内，关闭后回到原控件。

## 移动 Safari

请至少用一台真实 iPhone 的 Safari 验收；有 iPad 支持需求时也检查 iPad。桌面窗口缩窄可用于快速发现断点问题，但不能代替触屏和系统键盘检查。

- [ ] 竖屏打开工作区、笔记列表和编辑器，导航入口、返回操作和底部工具栏可见且可点。
- [ ] 横竖屏切换、滚动笔记、打开大纲/菜单/弹窗后，页面没有横向溢出、误滚背景或被键盘遮挡的操作按钮。
- [ ] 使用系统中文键盘编辑并完成输入法选字；编辑器不会因键盘弹出而跳动到错误位置，也不会误触快捷键。
- [ ] 长按、选中文字、复制粘贴、上传图片和调整图片宽度均可完成。
- [ ] 切换浅色和深色模式；刷新或重新打开页面后主题保持预期。
- [ ] 快速切换笔记、返回列表、再次打开原笔记，正文与保存状态正确。

## 长内容与滚动

在测试笔记中粘贴一篇包含多组 H1–H3、长段落、列表、任务清单、表格、代码块、图片和双向链接的 Markdown 文档（建议约 50 KB）。

- [ ] 编辑器打开、滚动到底部、选择标题大纲项目和正文查找时，没有明显卡死或整页滚动错位。
- [ ] 大纲标题和文档中的位置一致；点击标题后目标内容能进入可见区域。
- [ ] 在文首、中间和末尾分别插入、删除文字，保存后刷新；改动位置正确，周边内容没有丢失或重复。
- [ ] 桌面和移动端的正文滚动与工作区滚动边界正确；表格、代码块和图片不会把页面撑出屏幕。
- [ ] 长内容导出为 Markdown 后重新打开，标题、列表、任务项、表格和链接仍可读。

## 保存、恢复与版本冲突

### 自动保存与重开

- [ ] 新建笔记后连续输入，停止操作并等待保存完成；刷新 Safari，最新正文仍在。
- [ ] 编辑已有笔记后立即切换到另一篇，再回到原笔记；最后一段改动已保存。
- [ ] 关闭笔记标签页后重新打开应用，已保存内容保持完整。

### 离线草稿恢复

使用独立测试设备或浏览器窗口打开测试笔记。编辑一段内容后，在等待保存前关闭该客户端的网络，确认保存失败状态；恢复网络并刷新页面，检查应用提示是否保留并恢复未保存草稿。只有确认草稿已经恢复后才继续编辑或重新载入。

### 两个客户端同时编辑

1. 客户端 A 和 B 都打开同一篇测试笔记，确保两边看到相同的初始正文。
2. 暂时断开 B 的网络，在 B 中追加一段独特文字，等待离线保存失败；不要刷新或关闭 B。
3. 在 A 中追加另一段文字，等保存完成。
4. 恢复 B 的网络并重试保存。检查页面是否识别版本冲突，并保留 B 的本地文字，没有静默覆盖 A 的更新。
5. 复制或记录 B 中需要保留的文字后，再点击“重新载入最新版本”；确认加载内容包含 A 的更新。手动把需要的文字重新加入并保存，最后刷新确认两段内容都存在。
